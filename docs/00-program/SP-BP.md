# OpenDream Cloud SP / BP

> SP = Strategy Plan（战略规划）；BP = Business Plan（商业计划）。
> 本文把“AI Native 基建”从理念转为可执行的战略与商业路径。
> 总纲：[AI Native OS](AI-NATIVE-OS.md) · 分析：[5 看 3 定/SWOT](../01-research/OPPORTUNITY-5-3-SWOT.md)

## 0. 执行摘要

### 我们是谁

**企业 AI Native 基础设施**：AgentCore（Agent Runtime）+ AgentLoop（可观测/评测/实验/治理/安全/沙箱/回测）+ OpenCode Harness（云端/桌面）+ LoopForge（流程编排）+ 数字军团指挥中心（应用层）+ Capability/Governance。

### 我们解决什么

企业想成为 AI Native，但缺少自己的底座：
- Builder 构建应用难、分享难；
- Agent 只能问答，不能持续闭环；
- 流程中的角色无法数字化、复用；
- 多个 Agent 无法编成军团端到端作战；
- 管理者看不见、管不住、算不清；
- 私有化、安全、成本不可控。

### 我们的判断

1. AI Native 的竞争会从“模型/应用”转向“**基建 + 组织能力**”。
2. 企业不会只买一个 Agent 搭建器，而会建设自己的 **AI Native OS**。
3. **流程驱动角色数字人 + 军团 + 指挥中心** 是差异化核心。
4. **opencode + MCP** 提供云边一致的工具链与生态入口。
5. 私有化/开源是大型企业的刚性需求。

### 我们的策略

- **楔子**：软件研发交付（验证 AgentCore/AgentLoop/OpenCode Harness/LoopForge/军团/审批/评测）。
- **扩张**：客户运营 → 财务/供应链 → 全业务域。
- **产品**：开源核心 + 企业版 + 行业包 + 服务 + 生态。
- **护城河**：角色/SOP 资产、指挥中心数据、云边工具链、企业治理、生态。

# 第一部分：SP 战略规划

## 1. 愿景与使命

**愿景**：让每家企业都拥有自己的 AI Native 基建，让 AI 成为组织能力而非个人工具。

**使命**：以流程驱动角色数字人，以数字人编成军团，以指挥中心统一作战，让任何业务都能 AI Native。

**三年目标（方向性）**：

1. 成为企业 AI Native 基建的独立选择（非云绑定、非单点工具）。
2. 建立角色/SOP/军团/指挥中心的产品标准。
3. 形成可复制的行业方案与伙伴生态。

## 2. 三定

### 2.1 定战略

**战略定位**：企业 AI Native 基础设施提供商。

**战略选择**：
- 不做通用大模型；
- 不做单点垂直应用；
- 不做封闭 SaaS；
- 以 **平台 + 行业包 + 服务 + 生态** 变现；
- 以 **私有化/开源** 建立信任与差异化；
- 以 **软件交付** 为楔子，向全业务域扩张。

### 2.2 定目标

采用“3 个阶段 × 3 类指标”：

| 阶段 | 产品目标 | 商业目标 | 组织目标 |
| --- | --- | --- | --- |
| 0–12 个月 | 一条端到端 AI Native 闭环可复制 | 10–20 家设计伙伴；3–5 个付费试点 | 核心产品/交付/生态团队 |
| 12–24 个月 | OpenCode Harness 分享、数字军团指挥中心、真实执行 | 30–50 家企业客户；行业包收入 | 渠道/伙伴体系 |
| 24–36 个月 | AI Native OS 标准与生态 | 规模化 ARR；行业复制 | 区域/行业组织 |

> 数字为规划区间，需按实际资源与验证结果校准，不构成承诺。

### 2.3 定路径

```text
开源核心 + 设计伙伴
  → 软件交付楔子（真实闭环）
  → 客户运营/财务行业包
  → 企业 AI Native 底座
  → 生态市场与标准
```

**关键路径**：
1. 先把“一条闭环”做实（真实执行、可恢复、可治理）。
2. 再把“角色/SOP/军团”资产化、可复用。
3. 再把“Command Center”做成指挥标准。
4. 最后用行业包与伙伴规模化。

## 3. 目标客户与细分

### 3.1 客户分层

| 层级 | 特征 | 产品/服务 |
| --- | --- | --- |
| A. 大型企业 AI 平台部门 | 有预算、有团队、要私有化 | 企业版 + 服务 |
| B. 软件交付/研发效能中心 | 痛点明确、易验证 | 软件交付包 |
| C. 流程密集型部门 | 客服/财务/供应链 | 行业包 |
| D. 系统集成商/行业伙伴 | 有客户、有交付能力 | 伙伴版 + 分成 |
| E. 中小企业 | 预算有限、标准化 | 社区版/云托管（后续） |

### 3.2 首要 ICP

- 1000 人以上、多业务域；
- 有 AI/数字化预算与平台团队；
- 有私有化/合规要求；
- 愿意做 4–8 周试点；
- 有明确的流程负责人。

## 4. 产品组合与路线

| 产品 | 定位 | 阶段 |
| --- | --- | --- |
| OpenCode Harness | 云边 AI 原生 Harness 工程 | Alpha→Beta |
| AgentCore | Agent Runtime 环境 | Alpha→Beta |
| AgentLoop | 可观测/评测/实验/治理/安全/沙箱/回测 | Alpha→Beta |
| Orchestration / LoopForge | 角色数字人 + SOP + 军团 | Alpha→Beta |
| Command Center | 作战指挥中心 | Beta |
| Capability Center | 模型/MCP/Skill/Prompt | Alpha |
| Governance | 凭证/审计/配额/权限 | Alpha→Beta |
| 行业包 | 软件交付/客服/财务 | Beta |
| 生态市场 | MCP/角色/SOP 分享 | GA |

## 5. 护城河

1. **角色/SOP 资产网络效应**：复用越多，价值越大。
2. **指挥中心数据**：任务、风险、成本、复盘形成经营数据资产。
3. **云边工具链**：opencode + MCP 的一致体验。
4. **企业治理**：安全、审计、配额、私有化。
5. **行业包与伙伴**：可复制的交付能力。
6. **开源社区**：标准与生态入口。

## 6. 组织与能力建设

| 能力 | 建设 |
| --- | --- |
| 产品 | 平台产品 + 行业产品双线 |
| 研发 | 平台架构、AgentCore、AgentLoop、执行层、前端设计系统 |
| 交付 | 试点方法论、角色/SOP 工作坊 |
| 生态 | MCP/伙伴/开发者关系 |
| 市场 | 开源内容、案例、行业活动 |
| 安全 | 合规、审计、渗透、供应链 |

## 7. 伙伴策略

- **系统集成商**：行业交付、实施、客户关系；
- **MCP/工具厂商**：连接器与工具生态；
- **行业咨询**：流程梳理、角色设计；
- **云/基础设施**：私有云、K8s、模型服务；
- **高校/社区**：人才与开源贡献。

# 第二部分：BP 商业计划

## 8. 市场与机会（假设口径）

> 不使用未经验证的市场规模数字；以下为**建模框架**，需在试点中校准。

### 8.1 TAM / SAM / SOM

```text
TAM = 目标企业数 × 年度 AI Native 基建预算
SAM = 可服务企业数（区域/行业/私有化） × 客单价
SOM = 3 年可获取客户数 × 客单价 + 行业包/服务收入
```

### 8.2 收入结构

| 收入 | 说明 | 阶段 |
| --- | --- | --- |
| 企业订阅 | 按平台/节点/用量 | 0–12 月 |
| 行业包 | 角色包/SOP 包/连接器 | 6–24 月 |
| 实施服务 | 试点、流程梳理、集成 | 0–24 月 |
| 培训认证 | AI Native 角色/方法 | 12–36 月 |
| 生态分成 | MCP/角色/SOP 市场 | 24–36 月 |

### 8.3 定价框架（示意）

| 版本 | 价格逻辑 | 目标 |
| --- | --- | --- |
| 社区版 | 免费/开源 | 获客、社区 |
| 企业版 | 年度订阅（按规模/节点） | 主收入 |
| 行业包 | 年度订阅/一次性 | 提升客单 |
| 服务 | 人天/项目 | 试点与交付 |
| 伙伴版 | 分成/授权 | 规模化 |

> 具体价格需根据试点价值与竞争定价验证。

## 9. GTM 策略

### 9.1 阶段

1. **开源 + 设计伙伴**：建立可信度与案例。
2. **软件交付楔子**：用真实闭环证明价值。
3. **行业复制**：客户运营/财务包。
4. **伙伴规模化**：SI/咨询/云厂商。
5. **生态市场**：MCP/角色/SOP。

### 9.2 获客漏斗

```text
开源/内容 → 试用/演示 → 试点 → 付费 → 扩张 → 行业复制
```

### 9.3 销售动作

- 价值工作坊：识别流程/角色/指标；
- 4 周试点：一条闭环 + ROI 初算；
- 企业版：治理/SSO/HA/支持；
- 扩张：更多军团/业务域；
- 伙伴：联合交付。

## 10. 单元经济（框架）

```text
LTV = 年客单 × 毛利率 × 留存年数
CAC = 销售/市场投入 ÷ 新客数
回本周期 = CAC ÷ (年客单 × 毛利率)
```

关键杠杆：
- 提高行业包占比；
- 降低交付人力；
- 提高角色/SOP 复用；
- 提高续费/扩张。

## 11. 成本结构

| 成本 | 说明 |
| --- | --- |
| 研发 | 平台、AgentCore、AgentLoop、执行层、前端 |
| 云/算力 | 试点环境、模型调用 |
| 交付 | 试点、集成、培训 |
| 销售/市场 | 内容、活动、渠道 |
| 支持 | SLA、运维、安全 |
| 社区 | 开源维护 |

## 12. 三年财务情景（框架）

| 情景 | 假设 | 策略 |
| --- | --- | --- |
| 保守 | 付费试点少、交付重 | 控制成本，聚焦行业包 |
| 基准 | 设计伙伴转付费、行业包起量 | 平衡产品/交付 |
| 积极 | 伙伴规模化、生态分成 | 加大研发/市场 |

> 不在本文虚构具体营收数字；以试点转化率、客单、毛利率、CAC 回收期作为管理指标。

## 13. 里程碑

| 时间 | 里程碑 |
| --- | --- |
| 0–3 月 | 一条闭环 + 3 家设计伙伴 + 价值基线 |
| 3–6 月 | 软件交付包 + 5 家试点 + 首批付费 |
| 6–12 月 | OpenCode Harness 分享 + 数字军团指挥中心 Beta + 行业包 |
| 12–24 月 | 30+ 客户 + 伙伴体系 + 企业版 GA |
| 24–36 月 | 行业复制 + 生态市场 |

## 14. 关键风险与对冲

| 风险 | 对冲 |
| --- | --- |
| 产品范围过大 | 楔子策略，先闭环 |
| 真实执行难 | 先接 opencode/沙箱，分阶段 |
| 大厂竞争 | 私有化/开源/行业深度 |
| 交付重 | 行业包/伙伴/模板 |
| 安全事件 | 治理内建、审计、渗透 |
| 现金流 | 试点付费、控制成本 |

## 15. 90 天行动计划

1. **产品**：冻结范围，完成“Builder→应用→分享”和“任务→军团→指挥”两条旅程。
2. **技术**：Postgres 主库、NATS 队列、真实执行器 PoC。
3. **设计**：统一 IA/组件/UX，减少页签与概念重叠。
4. **商业**：3 家设计伙伴，4 周试点，ROI 基线。
5. **生态**：MCP 连接器 3 个，角色包 1 个，开源内容。
6. **组织**：明确产品/研发/交付/生态负责人。

## 16. 决策请求

需要管理层确认：

1. 是否以 **AI Native 基建** 为长期定位，而非单点工具；
2. 是否接受“先楔子、后扩张”的节奏；
3. 是否投入真实执行层（AgentCore/AgentLoop/OpenCode Harness）而非继续做演示；
4. 是否建立行业包与伙伴体系；
5. 是否以 3 家设计伙伴 + 4 周试点作为下一阶段硬指标。
