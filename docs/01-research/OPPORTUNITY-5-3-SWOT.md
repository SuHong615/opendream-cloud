# 5 看 3 定 · SWOT · 机会分析

> 对象：OpenDream Cloud — 企业 AI Native 基础设施。
> 关联：[SP/BP](../00-program/SP-BP.md) · [AI Native OS](../00-program/AI-NATIVE-OS.md)

## 一、5 看

### 1. 看宏观（Macro）

| 趋势 | 判断 | 影响 |
| --- | --- | --- |
| AI Native 成为企业战略 | 从“试点”转向“底座” | 基建需求上升 |
| Agent 从问答走向执行 | 长任务、工具调用、闭环 | AgentCore/AgentLoop 成为刚需 |
| 私有化/数据主权 | 金融/制造/政企强需求 | 开源/自托管优势 |
| 模型商品化 | 模型不是壁垒 | 价值转向编排/治理/数据 |
| 算力成本波动 | 成本敏感 | 模型路由/配额/本地模型 |
| 监管与审计 | AI 治理要求提高 | 审计/审批/可解释 |
| 开源生态 | MCP/Agent 标准 | 生态入口与标准化机会 |

### 2. 看行业（Industry）

| 赛道 | 现状 | 机会 |
| --- | --- | --- |
| 编码 Agent | LoopForge/Codex/Claude Code/opencode 强 | 以编码为楔子，扩展企业基建 |
| Agent 平台 | 云厂商托管、Dify/Coze 搭建 | 私有化、流程/角色/军团/指挥 |
| 工作流/RPA | 确定性流程强、AI 弱 | AI 原生 + 人工门禁 |
| 低代码/应用平台 | 应用搭建快、治理弱 | AI Native 应用 + 分享 + 治理 |
| SI/咨询 | 客户关系强、产品弱 | 伙伴生态 |
| 开源框架 | 灵活、无产品化 | 开箱即用底座 |

### 3. 看客户（Customer）

| 客户 | 痛点 | 未被满足 |
| --- | --- | --- |
| AI 平台部门 | 工具碎片、重复建设 | 统一 AI Native 底座 |
| Builder | 构建/分享难 | OpenCode Harness + MCP + 模板 |
| 领域专家 | 经验难数字化 | 角色数字人 + SOP |
| 业务负责人 | AI 不可见/不可控 | 作战指挥中心 |
| 开发者 | 云边割裂 | 统一工具链 |
| 安全/合规 | 影子 AI、不可审计 | 治理内建 |
| 高管 | 看不到 ROI | 组合价值与复盘 |

### 4. 看竞争（Competition）

| 竞争类型 | 代表 | 优势 | 我们的应对 |
| --- | --- | --- | --- |
| 编码 Agent | LoopForge | SOP/角色/沙箱体验 | 企业多域 + 指挥 + 治理 |
| 云 Agent 平台 | AgentCore 类 | 托管/生态 | 私有化/开源/可替换 |
| 应用搭建 | Dify/Coze | 上手快 | 流程+角色+军团+指挥 |
| RPA | UiPath | 确定性 | AI 原生 + 工具调用 |
| 自研 | 内部平台 | 定制 | 产品化 + 资产复用 |
| 模型厂商 | 基础模型 | 能力/价格 | 不绑定，做上层基建 |

### 5. 看自己（Self）

**优势**
- 全栈私有化：控制台/控制面/工作流/Agent/MCP/Skill/评测/桌面端；
- 4+1+1 平面叙事完整：AgentCore/AgentLoop/OpenCode Harness/LoopForge/指挥中心；
- 流程驱动角色数字人 + 军团 + 指挥中心的差异化；
- opencode + MCP 云边工具链；
- Apache-2.0 与开源社区潜力；
- 已有可运行原型与测试。

**劣势**
- Alpha，真实 AgentCore/AgentLoop 未完成；
- 产品 IA/UX 混乱，概念重叠；
- 持久化/异步/HA 未生产化；
- 品牌、案例、生态薄弱；
- 交付重，行业包不足；
- 团队/资金/渠道未知。

## 二、3 定

### 1. 定战略

**做企业 AI Native 基础设施，不做单点工具/封闭 SaaS。**

战略支柱：
1. AgentCore（运行时）
2. AgentLoop（质量/治理闭环）
3. OpenCode Harness（云边工程）
4. LoopForge（流程编排）
5. 数字军团指挥中心（应用层）
5. Capability/Governance（底座）

### 2. 定目标

| 维度 | 12 个月 | 24 个月 | 36 个月 |
| --- | --- | --- | --- |
| 产品 | 一条闭环可复制 | OpenCode Harness 分享 + 指挥中心 | AI Native OS 标准 |
| 客户 | 3–5 付费试点 | 30–50 客户 | 行业规模化 |
| 生态 | 3 个 MCP/角色包 | 伙伴体系 | 市场分成 |
| 组织 | 核心团队 | 行业/伙伴 | 区域/行业组织 |

> 区间为规划目标，需按资源校准。

### 3. 定路径

```text
开源核心
  → 设计伙伴 + 软件交付楔子
  → 真实 AgentCore/AgentLoop/OpenCode Harness
  → 行业包（客服/财务）
  → 企业 AI Native 底座
  → 生态市场
```

关键战役：
1. 真实闭环（不是 Demo）；
2. 角色/SOP 资产复用；
3. Command Center 指挥标准；
4. 行业包与伙伴。

## 三、SWOT

### Strengths（优势）

1. 完整私有化全栈，14 服务可运行；
2. 4+1+1 平面叙事（AgentCore/AgentLoop/OpenCode Harness/LoopForge/指挥中心）；
3. 流程驱动角色数字人 + 军团，差异化清晰；
4. opencode + MCP 云边工具链；
5. Apache-2.0，易建立信任；
6. 已有角色/SOP/画布/军团/审批/评测原型。

### Weaknesses（劣势）

1. 真实执行缺失，AgentCore/AgentLoop 仍是原型；
2. IA/UX 混乱，概念多、页签多；
3. 数据层/异步/HA 未生产化；
4. 品牌/案例/生态弱；
5. 行业包/交付方法论不足；
6. 资源与商业化未验证。

### Opportunities（机会）

1. 企业 AI Native 基建层空缺；
2. 私有化/合规替代；
3. Agent 从问答到执行的范式转移；
4. MCP 生态标准化；
5. 作战指挥中心新品类；
6. 行业角色包/SOP 包；
7. AI Native 组织转型服务；
8. 伙伴/渠道规模化。

### Threats（威胁）

1. 云厂商/模型厂商下沉；
2. 开源竞品/克隆；
3. 编码 Agent 向平台扩展；
4. 安全/合规事件；
5. 价格战/模型商品化；
6. 客户预算收缩；
7. 人才竞争；
8. 产品范围过大导致失焦。

### SWOT 策略矩阵

| | O | T |
| --- | --- | --- |
| **S** | SO：用全栈+四层叙事抢占 AI Native 基建；以 opencode/MCP 做云边入口；以角色/军团/指挥中心差异化 | ST：以私有化/治理对抗云厂商；以行业包对抗价格战；以开源社区对抗克隆 |
| **W** | WO：用设计伙伴补案例；用行业包补交付；用开源补品牌 | WT：收缩范围，先做一条闭环；避免与大厂正面拼模型/通用平台 |

## 四、机会点排序

| 机会 | 吸引力 | 可行性 | 优先级 |
| --- | --- | --- | --- |
| 软件交付军团（楔子） | 高 | 高 | P0 |
| OpenCode Harness 构建/分享 | 高 | 中高 | P0 |
| 作战指挥中心 | 高 | 中 | P1 |
| 客户运营行业包 | 高 | 中 | P1 |
| 财务/供应链行业包 | 中高 | 中 | P2 |
| 生态市场 | 高 | 低 | P2 |
| 中小企业云托管 | 中 | 低 | P3 |

## 五、关键假设与验证

| 假设 | 验证 | 失败信号 |
| --- | --- | --- |
| 企业愿意为 AI Native 基建付费 | 3 家设计伙伴付费试点 | 只愿为单点工具付费 |
| 流程驱动角色可行 | 角色复用 ≥ 40% | 每个场景重造 |
| 指挥中心是刚需 | 指挥官每周使用 | 只看报表不干预 |
| 云边一体有价值 | 桌面端周活 | 只用云端或只用本地 |
| 开源能获客 | 社区→试点转化 | 只有下载无商机 |

## 六、结论

- **战略上**：以 AI Native 基建为长期定位，以软件交付为楔子。
- **产品上**：4+1+1 平面能力必须完整，但按阶段交付；先闭环，再指挥，再生态。
- **商业上**：开源获客 + 企业版 + 行业包 + 服务 + 伙伴。
- **组织上**：产品/研发/交付/生态四线并进。
- **最大风险**：范围过大与真实执行缺失；必须用“一条闭环”约束路线。
