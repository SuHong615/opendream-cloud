## 1. 产品目标与成功定义

### 1.1 一句话定位

> 给每个工程师一间随身的 AI 工程云工作室：打开浏览器就有 4C8G 的 opencode，模型、技能、MCP、应用全部即取即用。

### 1.2 北极星指标（NSM）

**定义：周成功会话数（Weekly Successful Sessions, WSS）**

> 一次"成功会话"= 同一用户在同一工作区内、同一会话（session）中，**至少完成 1 次模型交互且产生 1 次成功工具/文件操作**，且该会话内无 P0 错误（网关 5xx 连续 3 次 / `model_gateway_unavailable`）。
> **拉起失败不计入 WSS 分母或错误**（拉起发生在会话之前），单独作为漏斗 S2 指标 `workspace.launch_fail_rate` 统计。
> 取周维度去重计数；数据来源：opencode `message` 事件 + `tool` 执行事件 + 平台错误事件，由计量服务聚合。

**为什么不是"周活跃工作区数"**：周活跃工作区（WAW）只反映"来了"，不反映"用成了"；WSS 同时约束了可用性与价值产出。WAW 作为**一级辅助指标**（North-star leading）。

### 1.3 指标树

| 层级 | 指标 | 定义 | 上线 3 个月目标 | 数据来源 |
| --- | --- | --- | --- | --- |
| 北极星 | **WSS 周成功会话数** | 见 1.2 | ≥ 3,000/周（按 1,000 活跃用户 × 3 会话估算） | 计量+事件 |
| L1 激活 | 首日激活率 | 注册当日产生 ≥1 个 WSS 的用户 / 当日注册用户 | ≥ 70% | 事件 |
| L1 留存 | 周留存（W2/W4） | 第 2/4 周仍产生 WSS 的用户 / 首周激活用户 | W2 ≥ 60%，W4 ≥ 45% | 事件 |
| L1 可靠性 | 工作区就绪 P95 | 首次进入→可交互 | ≤ 90s | 链路追踪 |
| L1 可靠性 | 会话错误率 | 出现 P0 错误的会话 / 总会话 | ≤ 1% | 错误事件 |
| L2 治理 | 模型策略采用率 | 被组织策略覆盖的用户 / 组织内活跃用户 | 100%（P0 强制） | 策略表 |
| L2 治理 | 配额预警触达率 | 触发 80% 预警并成功通知的比例 | 100% | 告警 |
| L2 能力 | Skill 上架成功率 | 通过评测并上架的 Skill / 提交评测的 Skill | ≥ 80% | 评测中心 |
| L2 能力 | 应用分享采纳率 | 被 ≥1 人访问的应用 / 创建的应用 | ≥ 60% | 应用中心 |
| L3 成本 | 单工作区日成本 | 4C8G 常驻 + 存储 + 网关成本 / 活跃工作区 | 可观测，不设硬目标（先度量） | 成本看板 |
| L3 成本 | 资源利用率 | 工作区 CPU 使用 P50 / 配额 | ≥ 30%（避免纯占坑） | 监控 |

### 1.4 转化漏斗（AARRR 裁剪）

```
访问落地页/邀请链接
  → [S1] SSO 登录成功           目标 ≥ 99%
  → [S2] 工作区首次就绪          目标 ≥ 99%（失败可重试后成功 ≥ 99.9%）
  → [S3] 首个会话产生（发第一条消息） 目标 ≥ 85% of S2
  → [S4] 首个成功会话（WSS 口径）    目标 ≥ 80% of S3
  → [S5] 次日回访（W1）          目标 ≥ 65% of S4
  → [S6] 能力消费（装 Skill/绑 MCP/用应用）目标 ≥ 40% of 活跃用户
  → [S7] 能力生产（发 Skill/建应用/分享）  目标 ≥ 10% of 活跃用户
```

漏斗埋点事件（G3/G4 必须实现）：`auth.login.success`、`workspace.launch.start/ready/failed`、`session.first_message`、`session.success`、`workspace.revisit`、`skill.install`、`mcp.bind`、`app.create`、`app.share`、`app.access`。

## 2. 范围边界（In / Out / 边界规则）

### 2.1 In Scope（本期，与 PLAN §3.1 一致）

- 多租户控制台（Web）、OIDC SSO、RBAC、用户 API Key
- 模型中心（注册表 + LiteLLM 网关 + 统一配置下发 + 配额计量）
- 每用户持久工作区（4C8G、PVC、自动拉起、显式销毁、域名访问）
- Skill 中心 / 评测中心（沙箱）/ 应用中心（1C2G、分享、SSO 域名）/ MCP 中心
- ACK 部署制品（Helm + Terraform）、CI/CD、可观测、备份
- 产品/架构/设计/评审/交付文档

### 2.2 Out of Scope（本期不做）

| 项 | 原因 | 后续 |
| --- | --- | --- |
| 移动端原生 App | 非核心验证路径 | 观察响应式 Web 使用数据 |
| 自研模型推理集群 | 走模型网关对接外部供应商 | 按采购需求评估 |
| 复杂计费/账单 | 仅做用量计量 + 配额，账单留接口 | 通过 R10.1 接口对接 |
| 多地域多活 | 单地域双 AZ 已满足本期 | 按合规/容灾要求演进 |
| 桌面端 opencode 客户端改造 | 上游只读，不 fork | 用上游原生能力 |
| 互联网免登录访问应用 | 安全红线（R6.4） | 需单独安全评审 |
| 组织外协作者/访客账号 | 本期仅组织内成员 | 见开放问题 Q7 |
| Agent 多引擎（Claude Code/Codex 作为后端） | 本期统一 opencode 引擎 | 竞品威胁 T-01，见 §8 风险 |
| 工作区子路径反代（`/w/{id}/`） | 上游资源为根绝对路径、`opencode_session` Cookie `path=/` 串会话（BASELINE §5-2 已关闭） | 仅子域名方案（ADR-003） |
| iframe 嵌入工作区（MVP） | 上游整页 SPA，焦点/快捷键冲突；Q2 再评估 | P2 可选（独立域 Cookie 验证通过后） |

### 2.3 边界规则（易被误解，必须写清）

| ID | 规则 |
| --- | --- |
| B1 | **一个用户默认 1 个工作区**（固定 4C8G）；多工作区为 P2（R3.8），上限由组织策略配置 |
| B2 | **"退出"= 关闭浏览器/结束会话，不触发销毁**；销毁只有三个入口：用户显式销毁、管理员强制销毁（审计留痕）、合规删除请求 |
| B3 | **工作区与应用解耦**：应用构建产物独立于工作区；工作区销毁不影响已部署应用运行（J6 异常路径已定义） |
| B4 | **应用固定 1C2G**，不可升配（本期）；超限表现为 OOM/重启并可在监控中观测 |
| B5 | `public` 分享 = **平台内已登录用户可见**；任何"匿名/互联网免登录"形态一律禁止 |
| B6 | 模型密钥、MCP 凭证**不下发到工作区/浏览器**；只以虚拟 Key 或网关注入形式出现 |
| B7 | 平台不删除用户数据，除非用户显式销毁或合规删除请求（30 天内完成） |
| B8 | **统一鉴权语义：跨租户/资源不存在 → 404 `not_found`；同租户无权限 → 403 `forbidden` + `reason=authz_forbidden`**（不泄露他租户资源是否存在） |
