# OpenDream Cloud 测试方案

> 目标：用分层测试保证“编排可交付、执行可恢复、治理可审计”，而不是只保证页面能打开。

## 1. 测试范围

| 域 | 范围 |
| --- | --- |
| 编排 | Main Bot、需求、军团、角色、SOP、审批、版本 |
| 执行 | 工作区、执行器、沙箱、产物 |
| 能力 | 模型、MCP、Skill、Prompt、Agent 模板 |
| 治理 | 审计、凭证、配额、Outbox/DLQ、可观测 |
| 洞察 | 评测、实验、成本 |
| 桌面端 | 配对、模型/MCP 同步、本地执行 |
| 非功能 | 性能、安全、兼容、HA/DR、可访问性 |

## 2. 测试策略

### 2.1 测试金字塔

```text
        E2E（关键旅程） 5%
      ─────────────────
      契约/集成测试 25%
    ─────────────────────
        单元测试 70%
```

- 单元：领域规则/状态机/权限/DSL；
- 契约：API schema、事件 schema、MCP；
- 集成：服务 + DB + Outbox；
- E2E：5 条关键旅程；
- 探索性：真实浏览器/桌面/执行器。

### 2.2 左移

- OpenAPI/DSL schema 变更先写契约测试；
- 每个新页面必须有空/加载/错误态；
- 每个新 API 必须有 4xx/权限/幂等测试；
- 每个 Run 状态迁移必须有状态机测试。

## 3. 测试环境

| 环境 | 用途 | 数据 |
| --- | --- | --- |
| Local | 开发自测 | SQLite + mock |
| CI | 每次提交 | SQLite + 临时 Postgres |
| Staging | 发布前 | Postgres + NATS + 沙箱 |
| Demo | 演示/试点 | 种子数据 |
| HA | 故障演练 | K8s 多副本 |

## 4. 功能测试矩阵

### 4.1 编排

| 用例 | 预期 |
| --- | --- |
| Main Bot 发送目标 | 创建 LegionRun，状态 running |
| 需求下达军团 | Requirement 关联 Run，状态 in_progress |
| 选择 SOP 模板创建定义 | 生成初始版本 |
| 画布加节点/连线/保存 | DSL 校验通过，版本递增 |
| 版本对比/回滚 | 差异正确，回滚生成新版本 |
| 角色创建/编辑 | 刷新/重启后保留 |
| 角色绑定 Agent 节点 | 画布显示角色 |
| 军团组建 | 绑定 SOP + 小队 |
| 下达战役 | SquadRun 生成 |
| 审批通过 | Run 继续 |
| 退回重做 | 上游任务重置，Run 继续 |
| 驳回 | Run failed |
| 审批越权 | 403 |

### 4.2 执行

| 用例 | 预期 |
| --- | --- |
| 工作区启动 | 可访问、超时回收 |
| 执行器探测 | 返回 installed/path |
| 沙箱隔离 | 无法访问宿主 |
| 产物写入 | Artifact 可追溯 |
| 执行失败 | 节点失败、可重试/DLQ |

### 4.3 能力/治理

| 用例 | 预期 |
| --- | --- |
| 模型连通测试 | 成功/失败可见 |
| MCP 工具策略 | 未授权调用 403 |
| 凭证不泄露 | API 只回显掩码 |
| 审计查询 | 可追溯操作者/时间/对象 |
| Outbox 重放 | 幂等，不重复副作用 |
| 配额超限 | 429/明确提示 |

### 4.4 桌面端

| 用例 | 预期 |
| --- | --- |
| 配对码 | 一次性、可吊销 |
| 模型同步 | 不在本地保存 provider key |
| MCP 自动安装 | 版本/权限可见 |
| 断网 | 本地可用，恢复后同步 |

## 5. 非功能测试

### 5.1 性能

- API P95 < 500ms（读）/ < 1s（写，不含执行）；
- 工作台首屏 < 2s；
- 100 并发 Run 创建不丢；
- 事件积压 10 万可恢复；
- 大画布 200 节点可操作。

### 5.2 安全

- 认证绕过、CSRF、越权、IDOR；
- 租户隔离（org_id 注入）；
- 凭证/日志脱敏；
- MCP 工具注入/越权；
- 依赖漏洞/许可证扫描；
- 沙箱逃逸测试（隔离环境）。

### 5.3 可靠性

- 服务重启后 Run 可恢复；
- Postgres 主从切换；
- NATS 重连/积压；
- Outbox 重复投递幂等；
- 备份恢复 RPO/RTO。

### 5.4 可访问性/兼容

- WCAG 2.1 AA；
- Chrome/Edge/Safari 最新两版；
- 1280/1440/1920 分辨率；
- 键盘操作与屏幕阅读器。

## 6. E2E 关键旅程

1. 管理员配置模型 → 创建角色 → 从模板创建 SOP → 组建军团 → 下达战役；
2. 交付负责人登记需求 → 工作台 Main Bot → 战役 → 审批；
3. 领域专家画布编辑 → 保存版本 → 运行；
4. 审批人通过/退回/驳回；
5. 桌面端配对 → 同步模型/MCP。

## 7. 测试数据

- 种子组织、角色、SOP、军团；
- Mock 模型服务；
- 测试 MCP server；
- 沙箱 fixture 仓库；
- 失败注入：超时、500、网络断开、重复事件。

## 8. 缺陷分级

| 级别 | 定义 | 处理 |
| --- | --- | --- |
| Blocker | 无法登录/执行/数据丢失 | 立即修复 |
| Critical | 核心旅程中断/越权 | 发布前修复 |
| Major | 功能错误但有绕过 | 本迭代修复 |
| Minor | 体验/文案 | 排期 |
| Trivial | 视觉细节 | 择机 |

## 9. 发布门禁

必须全部通过：

- 单元/契约/集成测试全绿；
- 关键 E2E 全绿；
- 无 Blocker/Critical；
- license check；
- 安全扫描无高危；
- 数据库迁移可回滚；
- 变更说明与回滚方案。

## 10. 当前差距

- E2E 50 条，但缺少真实执行器/沙箱/HA；
- 无性能/安全自动化；
- 无桌面端自动化；
- 无故障注入；
- 测试数据隔离不足。

## 11. 测试路线

| 阶段 | 内容 |
| --- | --- |
| P0 | 固化关键 E2E + API 契约 + 角色/画布/审批 |
| P1 | Postgres/NATS 集成、故障注入、性能基线 |
| P2 | 安全测试、桌面端自动化、HA/DR 演练 |
| P3 | 持续混沌工程与生产巡检 |
