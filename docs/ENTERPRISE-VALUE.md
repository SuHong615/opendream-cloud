# 企业价值与 AI 落地场景

> 这份文档回答三个问题：**企业为什么需要它、AI 具体能落在哪些业务场景、如何衡量提效**。
> 当前项目为 Alpha：场景可以演示/试点，生产落地需补齐 SSO、私有化、审计、SLA 与系统集成（见文末“落地边界”）。

## 1. 一句话价值主张

**把“会用 AI 的个人”升级为“可治理、可复用、可计量的企业 AI 生产力”。**

企业真正缺的不是一个聊天框，而是：

- 把模型、工具（MCP）、知识、流程、权限组合成**能完成业务任务的数字员工/专家小队**；
- 让这些能力**嵌入现有业务系统**（工单、ERP、CRM、代码库、数据平台），而不是另开一个入口；
- 对每次调用/每个任务做到**可观测、可审计、可配额、可人工接管**；
- 把一次成功经验沉淀为 **Skill / Prompt / 工作流模板**，让全组织复用。

## 2. 企业价值公式

```text
年度价值 =
  Σ(场景任务量 × 单任务节省时间 × 人力成本)
+ Σ(交付周期缩短 × 吞吐提升)
+ Σ(自动化解决率 × 单次服务成本)
+ 质量/风险损失下降
- 模型与算力成本
- 平台建设与运维成本
```

配套度量（建议每个场景上线前定义基线）：

| 维度 | 指标 | 说明 |
| --- | --- | --- |
| 效率 | 单任务耗时、周期时间、一次通过率 | 与人工基线对比 |
|  adoption | 周活用户、任务数、复用率 | 避免“演示很酷、无人使用” |
| 质量 | 返工率、缺陷率、人工修改比例 | 人工接管率是重点 |
| 成本 | 单任务模型成本、GPU/工时 | 按场景核算 |
| 风险 | 越权、敏感数据、需审批操作 | 人工门禁 + 审计 |
| 体验 | 等待时间、7×24 可用性 | 客户/员工满意度 |

## 3. 六类可落地场景（按企业部门）

### 3.1 研发与交付（最高确定性）

| 场景 | AI 如何落地 | 平台能力 | 建议度量 |
| --- | --- | --- | --- |
| 需求拆解与任务分派 | 专家小队：lead 拆需求→backend/QA/前端分工 | 数字员工、专家小队、工作流 | 需求到开发启动时间 |
| 代码生成/改造 | opencode 工作区 + 企业模型 + 仓库 MCP | 工作区、模型中心、MCP | 代码产出/人日、返工率 |
| 代码审查 | 代码审查 Skill + 规范 Prompt | Skill、Prompt、MCP(git) | 审查覆盖、阻塞问题发现率 |
| 测试生成与回归 | 测试执行 Skill + 测试平台 MCP | Skill、工作流、评测 | 回归周期、缺陷逃逸 |
| 发布与回滚 | 工作流编排 + 人工门禁 | 工作流、人工任务、审计 | 发布周期、变更失败率 |

**价值**：把重复编码、审查、测试、发布准备从“人找工具”变成“小队按流程执行”，研发把时间放在设计与决策上。

### 3.2 客户服务与运营

| 场景 | AI 如何落地 | 平台能力 | 建议度量 |
| --- | --- | --- | --- |
| 工单分诊/答复 | 客服小队：分诊→知识检索→草稿→人工发送 | 专家小队、MCP(CRM/知识库)、应用中心 | 首响时间、一次解决率 |
| 7×24 多语言客服 | 数字员工 + 企业知识 + 人工升级 | 数字员工、Memory、工作流 | 自动解决率、转人工率 |
| 客户问题复盘 | 每周自动汇总工单→归因→改进建议 | 工作流排班、实验中心 | 问题闭环周期 |
| 客户成功巡检 | 定时小队运行：健康度→风险→动作建议 | 定时排班、专家小队 | 流失预警命中率 |

**价值**：高频、标准化、知识密集的工单最适合“AI 先处理、人做升级/兜底”，直接降低单票成本与首响时间。

### 3.3 财务、采购与合规

| 场景 | AI 如何落地 | 平台能力 | 建议度量 |
| --- | --- | --- | --- |
| 发票/单据抽取 | 发票抽取 Skill + OCR/ERP MCP + 人工校验 | Skill、MCP、工作流 | 单票处理时长、准确率 |
| 对账与异常识别 | 财务小队：取数→比对→异常清单→人工审批 | 专家小队、Memory、工作流 | 对账周期、异常漏检 |
| 合同/条款审查 | 合同审查 Prompt + 法务知识 + 人工门禁 | Prompt、Memory、人工任务 | 审查时长、风险条款覆盖 |
| 付款/报销审批 | 工作流 + 规则 + 人工审批（强制） | 工作流、Guardrails、审计 | 审批周期、违规拦截 |

**价值**：财务场景规则明确、重复性高、错误代价高，适合“AI 做初筛/核对，人做最终审批”，在可控风险下显著提效。

### 3.4 数据与经营决策

| 场景 | AI 如何落地 | 平台能力 | 建议度量 |
| --- | --- | --- | --- |
| 自然语言取数 | 数据分析师数字员工 + 数仓 MCP + 只读 SQL 校验 | 数字员工、MCP、Memory | 取数等待时间、查询正确率 |
| 经营周报/月报 | 定时工作流：取数→分析→生成→人工确认 | 工作流、排班、应用中心 | 报表产出时间 |
| 指标异常归因 | 实验/评测 + 分析小队 | 实验中心、专家小队 | 归因时长、动作采纳率 |
| 数据资产问答 | Memory + 指标口径知识库 | Memory、Prompt | 口径一致率 |

**价值**：把“提需求等数据团队”变成“业务自助问答 + 数据团队审核”，释放数据团队产能。

### 3.5 HR、行政与内部服务

| 场景 | AI 如何落地 | 平台能力 | 建议度量 |
| --- | --- | --- | --- |
| 入职/离职办理 | 工作流 + HR 系统 MCP + 人工确认 | 工作流、MCP | 办理时长、遗漏率 |
| 政策问答 | HR 数字员工 + 制度 Memory | 数字员工、Memory | 自助解决率 |
| 面试安排/纪要 | 数字员工 + 日历 MCP | 数字员工、MCP | 协调耗时 |
| 内部 IT 支持 | 工单小队 + 知识库 | 专家小队、应用中心 | 一次解决率 |

**价值**：内部服务高频、规则清晰，AI 可承担 60% 以上的重复问答与流程推进。

### 3.6 销售与专业服务

| 场景 | AI 如何落地 | 平台能力 | 建议度量 |
| --- | --- | --- | --- |
| 投标/方案初稿 | Prompt 库 + 案例 Memory + 人工润色 | Prompt、Memory、应用中心 | 初稿时间、采纳率 |
| 客户拜访准备 | 小队：CRM→新闻/财报→简报 | 专家小队、MCP | 准备时间 |
| 报价/合同生成 | 工作流 + 模板 + 审批 | 工作流、人工任务 | 报价周期 |
| 交付文档 | 项目 Memory + 文档工作流 | Memory、工作流 | 文档产出时间 |

**价值**：专业服务“非标但可模板化”，AI 做资料整合与初稿，人做判断与客户关系。

## 4. 三个可测算的试点示例

> 以下为**假设示例**，用于立项测算，不是承诺值；上线前需用企业真实基线替换。

### 示例 A：200 人研发团队

- 假设：编码/审查/测试准备占 40% 工时，AI 覆盖 20% 任务，节省 15% 相关工时；
- 价值：200 × 40% × 15% ≈ **12 人年等效产能**（未计质量收益）；
- 成本：模型/算力 + 平台运维（按实际报价）；
- 先试点：1 个交付小队 + 代码审查 + 测试生成，4 周看“需求→合并”周期。

### 示例 B：月 10,000 工单的客服中心

- 假设：30% 工单可 AI 首答/草稿，人工处理每单 6 分钟，AI 后节省 3 分钟；
- 价值：10,000 × 30% × 3 分钟 ≈ **150 小时/月**，另加首响提升；
- 成本：模型调用 + 知识维护 + 人工抽检；
- 先试点：分诊 + 知识检索 + 草稿，人工一键发送，4 周看自动解决率与满意度。

### 示例 C：月 5,000 张发票的财务共享中心

- 假设：70% 发票可自动抽取，单票从 2 分钟降到 30 秒，人工只复核异常；
- 价值：5,000 × 70% × 1.5 分钟 ≈ **87.5 小时/月**，并降低录入错误；
- 风险控制：金额/供应商异常必须人工审批，全量审计；
- 先试点：发票 Skill + OCR MCP + 人工校验工作流，2 周验证准确率。

## 5. 企业落地路径（建议）

### 阶段 0：选场景（1 周）

- 选**高频、规则清晰、结果可校验、风险可控**的场景；
- 定义基线（耗时/成本/质量）与人工兜底方式；
- 明确数据边界：哪些数据可进模型、哪些必须脱敏/私有化。

### 阶段 1：POC（2–4 周）

- 接入 1 个企业模型 + 1–2 个业务 MCP + 1 个专家小队；
- 人工门禁 + 审计开启；
- 只对 10–30 名种子用户开放，收集“人工接管率/节省时间”。

### 阶段 2：试点（4–8 周）

- 扩到 1 个部门/1 条业务线；
- 建立 Skill/Prompt 复用库与评测集；
- 周度复盘：采纳率、质量、成本、风险事件。

### 阶段 3：规模化（3–6 个月）

- 接 SSO/组织架构/配额/成本分摊；
- 私有化/专有云、数据驻留、等保/审计；
- 多小队编排、7×24 排班、SLA 与值班；
- 用实验中心持续 A/B 模型与 Prompt。

## 6. 平台模块如何支撑企业价值

| 企业诉求 | 平台模块 |
| --- | --- |
| 用企业自己的模型/不绑定厂商 | 模型中心（供应商/密钥/路由） |
| 连企业系统与工具 | MCP 中心（工具协议/白名单/审计） |
| 把经验变成可复用资产 | Skill 中心、Prompt 库、工作流模板 |
| 让 AI 完成端到端任务 | 数字员工、专家小队、工作流 |
| 嵌入业务系统 | 应用中心（权限/分享/embed token） |
| 可控可审计 | Guardrails、人工门禁、审计、配额 |
| 持续变好 | 评测中心、实验中心、Memory/Experience |
| 7×24 运行 | 定时排班、可观测、告警 |

## 7. 落地边界（Alpha 阶段必须说明）

- 当前为 **Alpha**：内存存储、dev 登录、Mock 模型/执行，不可直接承载生产；
- 生产需补：企业 SSO/OIDC/SCIM、PostgreSQL/Temporal、KMS/Vault、私有化网络、等保/审计留存、HA/备份、SLA；
- 高风险场景（付款、合同、生产变更）必须保留**人工审批**，AI 只做建议/初筛；
- 企业数据进入模型前需完成分类分级、脱敏与合规评估；
- 不要用“AI 替代人”叙事，采用“AI 承担重复工作、人负责判断与责任”的协作模式。

## 8. 一页话术（对管理层）

> 我们不是再买一个 AI 聊天工具，而是把企业里**重复、知识密集、跨系统**的工作，交给可治理的数字员工/专家小队：
> 研发交付更快、客服首响更短、财务处理更省、数据取用更自助、风险操作有人工门禁与全量审计。
> 先从 1–2 个高频场景试点，用“节省工时、周期、自动解决率、风险事件”四个指标验收，再规模化。
