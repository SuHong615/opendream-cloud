# OpenDream Cloud UX 设计

> 4+1+1 平面对应五类工作台：指挥中心、LoopForge、OpenCode Harness、AgentLoop、能力/治理。
> 总纲：[AI Native OS](../00-program/AI-NATIVE-OS.md)

## 1. UX 原则

1. **按角色进入工作台**，不是按功能堆页签。
2. **指挥中心先看态势**，再下钻、再干预。
3. **编排是画布**：流程/角色/军团可视化。
4. **Harness 是工作区**：构建、调试、分享。
5. **AgentLoop 是质量台**：Trace、评测、实验、安全、回测。
6. **上下文不丢失**：右侧抽屉。
7. **说人话**：少框架术语，多业务语言。

## 2. 工作台

| 用户 | 工作台 | 核心动作 |
| --- | --- | --- |
| 指挥官 | 指挥中心 | 态势、干预、复盘 |
| 领域专家 | LoopForge | 流程、角色、军团 |
| Builder | OpenCode Harness | 构建、接入、分享 |
| 质量工程师 | AgentLoop | 观测、评测、实验、回测 |
| 管理员 | 能力/治理 | 模型/MCP/审计/配额 |
| 高管 | 指挥中心组合 | 价值、风险、扩张 |

## 3. 核心页面

### 3.1 指挥中心

- 数字孪生战场：业务/任务/军团/角色；
- 态势卡：战役、等待人工、失败、资源、成本；
- 风险列表；
- 干预按钮：暂停/退回/接管/重派；
- 复盘：周期/成功率/人工介入/成本/复用。

设计目标：**一屏看清、三次点击内干预、一战一复盘。**

### 3.2 LoopForge

- 流程画布：节点、角色、工具；
- 角色数字人：Prompt/模型/工具/门禁；
- 军团编制：小队/角色/SOP；
- 需求/战役/审批。

### 3.3 OpenCode Harness

- 左：工作区/文件/模板；
- 中：编辑器/画布；
- 右：运行/预览/日志；
- 顶：运行/发布/分享；
- 云端/桌面一致。

### 3.4 AgentLoop

- Trace 时间线：Run/Step/Tool/Observation；
- 评测：数据集/评测器/结果；
- 实验：A/B/版本对比；
- 安全/治理：策略/风险；
- 沙箱/回测：回放/仿真。

### 3.5 能力/治理

- 资产卡片/表格；
- 右侧抽屉编辑；
- 审计/配额/凭证/观测。

## 4. 状态设计

| 状态 | 呈现 |
| --- | --- |
| Loading | 骨架屏 |
| Empty | 引导 + 模板 |
| Running | 实时时间线/进度 |
| Waiting Human | 琥珀 + 审批入口 |
| Failed | 原因 + 重试/退回 |
| Blocked | 依赖/权限说明 |
| Passed/Failed | 评测结果 |

## 5. 文案

- 指挥：态势、卡点、风险、干预、复盘；
- 编排：流程、角色数字人、小队、军团；
- 工程：工作区、应用、模板、分享；
- 质量：Trace、评测、实验、安全、回测；
- 避免“赋能/抓手/闭环”等空话。

## 6. 可访问性

- 对比度 ≥ 4.5:1；
- 键盘可达；
- 抽屉焦点陷阱；
- 图表文本替代；
- 动效 reduced motion。

## 7. UX 指标

- Builder 首个应用 < 30 min；
- 指挥官干预 ≤ 3 次点击；
- 角色创建到发布 < 15 min；
- AgentLoop 评测结果可读；
- SUS > 75。

## 8. 当前问题

1. 只有 LoopForge 一个入口，未分角色；
2. AgentCore/AgentLoop/OpenCode Harness/指挥中心没有独立工作台；

4. 指挥中心只有概览卡片；
5. 质量闭环分散在评测/实验/观测；
6. 云边 Harness 未统一。
